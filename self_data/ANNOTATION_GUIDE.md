# Annotation Starter Guide — ke / peizhou / chaoyu

This guide walks through finishing the food-inventory annotation pipeline for three participants: **ke**, **peizhou**, **chaoyu**. The deliverable for each participant is:

1. **Receipts** in `participants/<p>/receipts/` covering every item that ever appears in any session.
2. **Reference image** for every item (one folder under `participants/<p>/reference_images/<instance_id>/`).
3. **Populated `ledger.json`** at `participants/<p>/ledger.json` — the final record, with all purchase + usage + depletion events and per-session snapshots.

`ledger.json` is the source of truth. `item_mapping.json` is just an intermediate scratchpad for the LLM-assisted matching step — once a session's events and snapshot are in the ledger, the mapping file is no longer needed (e.g. giraffe has no item_mapping.json files at all because its events were recorded directly via `controlled_batch.py`). Don't treat the absence of `item_mapping.json` as a missing deliverable; verify against the ledger snapshot instead.

Action-stage labels (`actions.json`) are **not** required.

## 1. Pipeline mental model

```
receipts/<date>.txt                    (list of purchases, manually authored)
        │
        ▼  intilization.py --participant <p>
ledger.json                            (items + purchase events seeded)
        │
        │  per session, per video:
        │    annotations/<session>/amount.txt   ← human-written
        │
        ▼  llm_amount_converter.py --participant <p>          (proposes mapping)
annotations/<session>/item_mapping.json
        │  human reviews/edits the mapping
        ▼  llm_amount_converter.py --participant <p> --confirm
ledger.json                            (usage events + per-session snapshot)
        │
        ▼  record_depletion.py --participant <p> --review
depletions/<date>.txt   (list of items gone but never measured to 0)
        │  human reviews
        ▼  record_depletion.py --participant <p>
ledger.json                            (depletion events recorded)
```

`reference_images/` is independent — populate it any time after the items exist in the ledger.

## 2. File formats (read this before touching anything)

### 2.1 `receipts/<date>.txt`

One item per line, comma-separated:

```
item name, count[, package_amount]
```

- `item name` — free text, becomes `visual_class` and (snake-cased) the `instance_id` prefix.
- `count` — how many packages were bought (use `1` for a single tub of yogurt; use `6` for 6 chinese sausages bought together but tracked as one item).
- `package_amount` — optional, free text like `454g`, `12 count`, `1.5L`. Leave blank if unknown.

Example (`participants/chaoyu/receipts/20260319.txt`):
```
Chinese sausage, 1, 6 count
beech mushroom, 1, 167g
garlic, 1, 3.7 count
green onion, 1, 12 count
yellow bell pepper, 1, 1 count
```

The filename `<date>.txt` (yyyymmdd) is the purchase date; events get timestamped at midnight.

### 2.2 `annotations/<session>/amount.txt`

One line per item used in this session:

```
item_name value_before [value_after]
```

- `value_before` — amount at start of session.
- `value_after` — amount at end of session. Omit if the item is fully used up; you can also write `depleted` after the number.
- For `unit: g` items, values are grams. For `unit: count` items (eggs, tomatoes), values are counts.
- Item name is free text — it does **not** have to match the ledger exactly; the LLM step matches it to a ledger `instance_id`.

Example (`participants/kailai/annotations/20260310-195710/amount.txt`):
```
Napa cabbage 724 546
Beef steak 453 232
Rice 506 385
```

### 2.3 `annotations/<session>/item_mapping.json` (intermediate, not a deliverable)

Generated by `llm_amount_converter.py`, then human-edited. Once you run `--confirm`, the events land in `ledger.json` and this file is no longer load-bearing — keep it for traceability, or delete it; either is fine. If a session's events were recorded by some other path (manual editing, `controlled_batch.py`, etc.) it's normal for this file to not exist.

```json
{
  "_comment": "Review and edit mappings below. Run with --confirm to apply.",
  "mapping": {
    "Napa cabbage": "napa_cabbage_20260310",
    "Beef steak": "ribeye_beef_steak_20260310"
  }
}
```

Keys = exactly the item-name tokens in `amount.txt`. Values = `instance_id` from the ledger (look in `ledger.json → items`).

### 2.4 `ledger.json`

Auto-managed. Three top-level keys you may inspect:
- `items[instance_id]` — `{visual_class, receipt_raw, unit, package_amount, ...}`
- `events[]` — chronological list of `{time, type: "purchase"|"usage"|"depletion", item, ...}`
- `snapshots[session_id]` — per-session `{instance_id: {starting, used, remaining, ...}}`

Don't hand-edit unless you're fixing a typo in `package_amount` or similar metadata.

### 2.5 `reference_images/<instance_id>/`

One folder per ledger item, named exactly with the `instance_id`. Inside, place at least one image (any common format — `product.webp`, `front.jpg`, etc. are all fine).

Example: `participants/kailai/reference_images/atlantic_salmon_center_cut_loin_20260330/product.webp`

### 3B. **peizhou** — receipts done, usage loop blocked on Chinese names

**State:**
- 41 ledger items (purchase events) from 3 receipts.
- 11 sessions with `amount.txt` already filled, all in **Chinese**.
- `translation.txt` available at `participants/peizhou/translation.txt` (Chinese → English mapping).
- 0 usage events / 0 snapshots / 0 item_mapping files.

**To do:**

1. **Verify receipt coverage**: scan all 11 amount.txt files, confirm every Chinese item name maps via `translation.txt` to something in the existing ledger. If you find an item used but not on any receipt, add it to a new receipt file (use the date of the first session that uses it) and re-run step 2.

   ```bash
   python annotating/intilization.py --participant peizhou
   ```

   (Idempotent — only adds new items.)

2. **Run the mapping loop**, one session at a time (chronologically):

   ```bash
   # Step A: propose mapping for the next unprocessed session
   python annotating/llm_amount_converter.py --participant peizhou
   ```

   This writes `annotations/<session>/item_mapping.json`. Open it and verify each Chinese key resolves to the right `instance_id`. Cross-reference `translation.txt` if unsure. Common pitfalls:
   - Same English name might match two ledger items from different purchase dates — pick the one purchased before this session and not yet depleted.
   - A receipt item you didn't add but the LLM hallucinated a match for — fix it manually.

   ```bash
   # Step B: confirm and record
   python annotating/llm_amount_converter.py --participant peizhou --confirm
   ```

   Repeat A → review → B until the script prints "Nothing to process".

3. **Identify depletions** (items that were used up but you never wrote a final `0` for them):

   ```bash
   python annotating/record_depletion.py --participant peizhou --review
   ```

   It prints suggested lines. Save them to `participants/peizhou/depletions/<today>.txt`, edit if needed (add `, reason` after the instance_id, e.g. `pasta_20260323, finished in session 20260325-193840`), then:

   ```bash
   python annotating/record_depletion.py --participant peizhou
   ```

4. **Reference images**: 41 items × one product photo each. Folder name = `instance_id`.

## 4. Verifying you're done

For each participant, run these sanity checks against the **ledger** (the source of truth):

```bash
# (a) Every video session has a snapshot in the ledger
python -c "
import json, os
P = 'ke'  # change to peizhou, chaoyu
base = f'participants/{P}'
ledger = json.load(open(f'{base}/ledger.json'))
snaps = set(ledger.get('snapshots', {}))
videos = set(os.listdir(f'{base}/videos'))
missing = sorted(videos - snaps)
print('sessions without snapshot:', missing if missing else 'none')
"

# (b) Every item referenced by an event exists in ledger.items
python -c "
import json
P = 'ke'
base = f'participants/{P}'
ledger = json.load(open(f'{base}/ledger.json'))
items = set(ledger['items'].keys())
bad = sorted({e['item'] for e in ledger['events'] if e['item'] not in items})
print('events referencing unknown items:', bad if bad else 'none')
"

# (c) Every ledger item has a reference image folder
python -c "
import json, os
P = 'ke'
base = f'participants/{P}'
ledger = json.load(open(f'{base}/ledger.json'))
ref = f'{base}/reference_images'
missing = [iid for iid in ledger['items'] if not os.path.isdir(f'{ref}/{iid}')]
if missing:
    for m in missing: print('missing image folder:', m)
else:
    print('all', len(ledger['items']), 'items have reference_images/')
"
```

When all three checks return clean, the participant is done. (Note: `item_mapping.json` is intentionally not checked — see §2.3.)

## 5. Troubleshooting

- **`llm_amount_converter.py` says "Nothing to process" but I haven't started**: it processes sessions chronologically and only the *next* unprocessed one. If session N has no `item_mapping.json` yet, it works on that. Run without `--confirm` first to generate the file.
- **`item_mapping.json` exists but I want the LLM to redo it**: delete the file, re-run without `--confirm`.
- **Item appears in `amount.txt` but isn't in the ledger**: add it to a receipt and re-run `intilization.py`. The pipeline never auto-creates items mid-session.
- **LLM picks the wrong `instance_id` (e.g. picks an already-depleted one from an earlier purchase)**: just edit `item_mapping.json` manually before `--confirm`.
- **Snapshot is wrong after `--confirm`**: don't hand-edit `ledger.json`. Instead, delete the `events` for that session and the `snapshots[session]` entry, fix `amount.txt` and `item_mapping.json`, re-run with `--confirm`.
